# こうちゃんの大冒険

![こうちゃんの大冒険のキービジュアル](public/images/title/key-visual.webp)

**いつもの公園が、今日はちょっとした大冒険。**

こうちゃんと一緒に公園を探検する、選択式のブラウザゲームです。
すべり台で遊んだり、どんぐりを探したり、おやつでひとやすみしたり。
こうちゃんの「いやいや」にも向き合いながら、親子で楽しいおでかけを目指します。

**[ゲームで遊ぶ](https://kouchan-game.vercel.app/)** · [サウンドトラック](https://kouchan-game.vercel.app/soundtrack)

## どんなゲーム？

- **公園を自由に探検** — 地図から行き先を選び、すべり台・砂場・池・芝生広場などで遊べます。探検を続けると、特別な場所が見つかることも。
- **親子のペースでおでかけ** — こうちゃんの体力と機嫌、親の体力と余裕を見ながら、遊びと休憩のバランスを考えます。
- **おやつを選んで出発** — 6種類のおやつから2つをバッグへ。休憩や「いやいやタイム」で役立ちます。
- **毎回ちがうできごと** — てんとう虫との出会いや噴水など、公園では思いがけないできごとが起こります。
- **発見と記録を楽しむ** — 見つけたものを集め、帰宅後のスコアやランクをチェック。ハイスコアや直近の記録も残ります。
- **ミニゲームと音楽のごほうび** — 冒険を通じてミニゲームや新しい曲が解放されます。

スマートフォンのタップ操作と、パソコンのマウス・キーボード操作に対応しています。
PWAに対応しているので、スマートフォンのブラウザからホーム画面に追加して起動することもできます。

## あそびかた

1. タイトル画面から進み、「きょうのおやつ」を2つ選んで出発します。
2. 公園の地図で行き先を選び、それぞれの場所で行動します。行動するとゲーム内の時間が進みます。
3. 体力や機嫌が下がってきたら、ひとやすみやおやつを使いましょう。
4. 「いやいやタイム」になったら、こうちゃんのセリフや様子をヒントに対応を選びます。
5. ゲーム内で12時になるか、公園の出口へ向かうと結果発表です。

冒険はゲーム内の朝9時から始まります。親子の体力や親の余裕がなくなると、途中でGAME OVERになることも。無理をせず、帰るタイミングも考えてみてください。

### 操作

| 操作方法 | 本編の操作 |
| --- | --- |
| スマートフォン | 行き先やコマンドをタップ |
| マウス | 行き先やコマンドをクリック |
| キーボード | 矢印キーで選択、Enter / Spaceで決定 |

詳しいルールは、ゲーム内の「あそびかた」から確認できます。

### 途中から再開するには

公園の地図に戻るたびに、進行状況を自動保存します。途中でやめた場合は、タイトル画面の「つづきから」で、最後に保存された地図の状態から再開できます。

進行状況、ハイスコア、ミニゲームの記録、解放した曲やサウンド設定などは、遊んでいるブラウザの`localStorage`に保存します。別の端末やブラウザとは共有されず、ブラウザのサイトデータを削除すると保存内容も消えます。

## ミニゲーム

本編での発見をきっかけに、ミニゲームが遊べるようになります。

| タイトル | 内容 |
| --- | --- |
| どこまで行ける？ | 枝をよけ、こもれびを集めながら森の小道を進むエンドレスゲーム。加速を使って自己ベストを目指します。 |
| 枝の上のてんとう虫 | 枝を左右に傾け、てんとう虫が飛んでいかないようにバランスをとるゲーム。ステージをクリアすると、エンドレスにも挑戦できます。 |

それぞれの画面に操作案内があります。プレイ中は一時停止でき、別のタブやアプリに切り替えたときも自動で一時停止します。

## サウンドトラック

ゲームで流れるBGMを、[サウンドトラックページ](https://kouchan-game.vercel.app/soundtrack)で聴くことができます。
全曲再生・シャッフル・リピートに対応し、冒険やミニゲームの達成状況に応じて、うた入りの特別な曲も追加されます。

一部の楽曲には、こうちゃんの父の原曲・演奏や、こうちゃんの鼻歌を使用しています。編曲・音楽生成にはSunoを使用しており、曲ごとの制作情報はサウンドトラックページに掲載しています。

## ローカルで動かす

このプロジェクトでは、Docker内のNode.js 24を使って開発しています。起動方法は、Dockerを使う方法と、パソコンにNode.jsを直接インストールする方法の2つです。初回の環境準備にはインターネット接続が必要です。3000番ポートを使う別のアプリがある場合は、先に停止してください。

### 1. Dockerで起動する（推奨）

必要なものは、**Docker（Docker Composeを含む）**と**Git**です。Docker Desktopなどをインストールし、Dockerを起動しておきます。この方法では、Node.jsとnpmはコンテナ内に用意されるため、パソコンへの個別インストールは不要です。

ターミナルで以下を1行ずつ実行します。

```bash
git clone https://github.com/kazuhitotakao/kouchan-game.git
cd kouchan-game
docker compose up --build
```

初回はDockerイメージの準備と依存パッケージのインストールに時間がかかります。

すでにリポジトリを取得済みの場合は、そのフォルダに移動してから`docker compose up --build`を実行してください。

#### 補足：Docker環境をVS Codeで開く（任意）

[Dev Containers](https://code.visualstudio.com/docs/devcontainers/containers)は、上の手順で使うDockerコンテナ内の開発環境に、VS Codeを接続して編集するための機能です。

1. VS CodeにMicrosoft製の「Dev Containers」拡張機能をインストールします。
2. VS Codeでこのリポジトリのフォルダを開きます。
3. コマンドパレットから`Dev Containers: Reopen in Container`を実行します。

同梱の`.devcontainer/devcontainer.json`が、`app`サービスの`/app`を開きます。npmコマンドは、コンテナに接続したVS Codeのターミナルで実行してください。

### 2. Node.jsで直接起動する

必要なものは、**Node.js（npmを含む）**と**Git**です。Docker環境とそろえるため、**Node.js 24系**を推奨します。先にインストールしておきます。

ターミナルで次のコマンドを実行し、Node.jsが`v24.`で始まるバージョンであることと、npm・Gitが使えることを確認します。

```bash
node --version
npm --version
git --version
```

その後、以下を1行ずつ実行します。

```bash
git clone https://github.com/kazuhitotakao/kouchan-game.git
cd kouchan-game
npm ci
npm run dev
```

### 起動後の確認・終了（Docker・Node.js共通）

Dockerで起動した場合も、Node.jsで直接起動した場合も、確認先と終了方法は同じです。

- 開発サーバーの起動が完了したら、ブラウザで[http://localhost:3000](http://localhost:3000)を開きます。
- 起動コマンドを実行したターミナルは、起動中は開いたままにします。
- 終了するときは、起動コマンドを実行したターミナルで`Ctrl + C`を押します。

### 主なコマンド

Dockerを使う場合、以下のnpmコマンドはコンテナ内で実行します。Dev Containersを使わない場合は、`docker compose exec app npm run typecheck`のように実行できます。

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 開発サーバーを起動 |
| `npm run typecheck` | TypeScriptとVueテンプレートの型を確認 |
| `npm run build` | 本番向けにビルド |
| `npm run preview` | ビルドしたアプリをローカルで確認 |
| `npm run generate` | 静的ページを生成 |
| `npm run generate-icons` | 元画像からPWA・ホーム画面用のアイコンを生成 |

## 技術構成

| 用途 | 技術 |
| --- | --- |
| フレームワーク | Nuxt 3 / Vue 3 |

### ディレクトリ構成

```text
pages/          本編・ミニゲーム・サウンドトラックのページ
components/     ステータス表示やゲーム画面などの部品
composables/    ゲーム進行・判定・音声・操作の処理
data/           場所・おやつ・イベント・ミニゲームなどの設定
utils/          保存・スコア表示・音声などの共通処理
types/          ゲームで使用する型定義
assets/css/     ゲーム画面のスタイル
public/         画像・音源・アイコン
.github/        型チェック・ビルド・自動マージのワークフロー
```

## 開発の進めかた

作業ブランチを作成し、`develop`向けにPull Requestを作成します。

- ブランチ名は`feat/`・`feature/`・`fix/`・`refactor/`・`chore/`のいずれかで始めます。
- コミットメッセージは、日本語のConventional Commits形式にします（例：`feat: 新しい遊び場を追加`）。
- `develop`と`main`には直接pushしません。
- 対象のPull Requestでは、GitHub Actionsが型チェックとビルドを行い、成功後に`develop`へsquash mergeしてリモートの作業ブランチを削除します。
- Vercelの自動デプロイは、`main`ブランチを対象にしています。
